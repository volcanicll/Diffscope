Features

Built for the act of reviewing

Not another git log in a sidebar. Every control is aimed at one question: what changed, and should it ship?

Word-level diffs, side by side

Split or unified, with the exact word highlighted inside the line. New and deleted files use one column. Unchanged context folds away 100 lines at a time, or all at once.

Viewed, and remembered

Mark a file viewed and it collapses. It opens again the moment it changes. Lockfiles, snapshots and node_modules start collapsed.

Comments that leave the app

Click a line, or use J/K and Enter; write on the hunk. ⌘⇧M copies every comment as Markdown, with the diff around it.

An AI pass before you start

Claude Code, Codex, OpenCode or Pi — whichever you already signed in to — summarizes the change, groups files by intent and points at the lines worth reading. Read-only, kept until you ask again.

Pull requests, reviewed locally

Fetch the PR's commits into your clone and review them exactly like local changes — threads under their lines, replies, resolve, and submit a comment, approval or request for changes.

Code · Tests · Docs Viewed per group New commits banner

A terminal beside the diff

Run the tests, rebase, or ask an agent — in a real pty with tabs, docked at the bottom or the right. ⌃` opens it anywhere.

History, branches, repository

Browse commits, review any of them against its first parent, compare a branch with its merge base, or read any file in the repository browser.

One command bar for everything

⌘K runs any action by name, ⌘P jumps to a file, ⇧? lists every shortcut. The review stays under your fingers.

Native by construction

Your git was already fast.
Reading it shouldn't be slow.

The whole window is one retained tree of UI elements, drawn by MyGo on the GPU. No webview, no embedded browser, no JavaScript runtime — just Go, system fonts, the system theme and the accent color.

  • ✓Work off the main thread. Git commands, file reads and agent runs happen in the background; late results are dropped by generation, so a slow command never paints over fresh state.
  • ✓Rebuild only what changed. A file's contents arriving rebuilds that card — not the review.
  • ✓Keyboard first. ⌘K commands, ⌘P files, J/K hunks, N AI notes, ⌃` terminal.

Get started

Four ways to open a review

Install the app, add the command line tool, and point it at a repository.

01 Uncommitted changes

diffscope

Run it inside a repository. Switch between All, Staged and Unstaged from the toolbar.

02 A commit

diffscope HEAD~1

Any revision works. Review it against its first parent, with the message pinned above the diff.

03 A pull request

diffscope --pr 123

Also owner/repo#123 or a PR URL. Public PRs need no token.

04 Another repository

diffscope ../other-repo

Each repository opens in its own window; ⌘O opens a folder from a review.
